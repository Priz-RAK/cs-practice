В ней вы независимо от других работаете над задачей: добавляете функцию, исправляете баг, экспериментируете.
А вот с физической точки зрения ветка — это просто указатель (ссылка) на конкретный коммит в истории проекта. Git находит общего предка — коммит, от которого когда-то разошлись две ветки.
Затем он сравнивает изменения, которые были сделаны в обеих ветках после этого общего пункта.
Если нет конфликтов (то есть в обеих ветках одни и те же строки кода не меняли по-разному), Git может просто «перемотать» указатель целевой ветки вперёд — это называется fast-forward. Новый коммит при этом не создаётся.
Если конфликты есть, Git не сможет автоматически объединить изменения. Он остановит процесс и попросит вас вручную разрешить конфликт (например, выбрать, какую версию файла оставить). После этого создаётся специальный коммит слияния (merge commit). У такого коммита два родителя: последний коммит целевой ветки и последний коммит сливаемой ветки. Так сохраняется история обеих линий разработки.
